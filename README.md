# Протокол 65 · Защити остров

Обучающая игра о трёх ИТ-профессиях: программист, системный администратор, специалист по защите информации. Участники играют каждый на своём компьютере, ведущая (Маргарита Евгеньевна) управляет игрой из отдельной панели.

## Как проходит игра

1. Ведущая открывает `/admin`, вводит PIN и начинает **сеанс** (например, «5Б · 4 октября»).
2. Участники открывают адрес игры и выбирают героя. Имя присваивается автоматически: прилагательное в роде героя + герой («Отважная Чудо-кошка», «Хитрый Бэт-кот»). В пределах сеанса прилагательные не повторяются. Число участников заранее не задаётся.
3. Каждый проходит короткое обучение в своём темпе и нажимает «Готов».
4. Ведущая видит, сколько человек готово, и нажимает «Запустить». У всех готовых идёт отсчёт 3-2-1, и стартует этап. Кто дочитал обучение позже, запускается следующим нажатием.
5. Время этапа: от старта до завершения плюс штрафные секунды за ошибки. Время считает сервер, поэтому обновление страницы его не сбрасывает: участник возвращается туда, где был.
6. Кнопка «Завершить этап» останавливает тех, кто ещё играет: им ставится «не завершил», и они переходят дальше.
7. После трёх этапов ведущая нажимает «Финал: вызвать союзника», и финальная заставка появляется у всех.
8. «Завершить сеанс» закрывает игру. Результаты остаются в разделе «Прошлые сеансы».

В панели ведущей видны статус каждого участника (обучение / готов / играет / прошёл игру, на связи или нет), время по каждому этапу со штрафами и ошибками, общее время и место. В общий зачёт попадают только те, кто прошёл все три этапа сам.

## Запуск локально

Нужен Node.js 20.6 или новее.

```sh
npm install
ADMIN_PIN=1234 npm start
```

Игра: http://127.0.0.1:3000, панель ведущей: http://127.0.0.1:3000/admin.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADMIN_PIN` | — (обязательна) | PIN панели ведущей, 4–12 цифр |
| `HOST` | `127.0.0.1` | на каком адресе слушать |
| `PORT` | `3000` | порт |
| `DATA_DIR` | `./data` | где хранить сеансы (по JSON-файлу на сеанс) |

Тесты игровой логики: `npm test`.

## Развёртывание на Gentoo (OpenRC + обратный прокси)

```sh
echo 'net-libs/nodejs npm' >> /etc/portage/package.use/nodejs   # нужен npm
emerge --ask net-libs/nodejs
useradd --system --home-dir /var/lib/proto65 --shell /sbin/nologin proto65

git clone https://github.com/thua48xsen3iemicy-boop/proto65.git /opt/proto65
cd /opt/proto65 && npm ci --omit=dev

cp deploy/proto65.env.example /etc/proto65.env      # впишите ADMIN_PIN
chown root:proto65 /etc/proto65.env && chmod 640 /etc/proto65.env

cp deploy/proto65.openrc /etc/init.d/proto65 && chmod +x /etc/init.d/proto65
rc-update add proto65 default
rc-service proto65 start
```

Лог пишется в `/var/log/proto65/proto65.log`, данные лежат в `/var/lib/proto65` (их стоит включить в резервное копирование).

Пример конфигурации nginx: `deploy/nginx.conf.example`. Игру можно разместить в корне сайта или в подкаталоге (`/proto65/`). Главное — пробросить WebSocket (заголовки `Upgrade` и `Connection`). Без этого Socket.IO всё равно работает через long-polling, но медленнее.

Обновление: `cd /opt/proto65 && git pull && npm ci --omit=dev && rc-service proto65 restart`. Перезапуск даже во время урока не теряет время и прогресс: они хранятся на сервере, а участники и панель переподключаются сами.

## Устройство

```
server/
  index.js          HTTP + Socket.IO: события участников и ведущей
  game.js           правила: участники, этапы, время, штрафы (без сети — покрыто тестами)
  store.js          сеансы в JSON-файлах с атомарной записью
  heroes.js         герои и их род
  adjectives.json   прилагательные для имён (можно дополнять)
public/
  index.html, js/app.js      игра участника
  admin.html, js/admin.js    панель ведущей
  css/, images/
deploy/             OpenRC-сервис, файл настроек, пример nginx
test/               тесты игровой логики (node --test)
```
